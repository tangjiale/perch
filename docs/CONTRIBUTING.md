# 开发规范

适用栖点正式 Tauri 应用。仅阅读本次任务相关章节；当前行为以代码和实际验证为准，目标方案不等于已交付能力。

## 1. 范围与流程

1. 明确用户目标，确认修改模块及现有改动；有 Git 时检查状态，无 Git 时不要假设可回滚。
2. 从模块入口和调用者开始，按证据读取相关文件；不默认扫描依赖、产物、JRE 和历史截图。
3. 复用现有组件与接口，修改保持可审查；仅在减少真实复杂度时新增抽象。
4. 按第 5 节选择验证。修复失败后重跑相关检查，通过后不反复扩测。
5. 报告行为变化、实际检查和剩余限制。只有改变契约、存储、用户流程或发布行为才补相应文档，不为每次文案修改追加长记录。

常规工作单代理完成。并行仅用于彼此独立且值得分工的任务，明确文件所有权、交付物与验证，最多 2 个子代理；禁止多个代理同时修改公共文件，不递归委派。

## 2. 技术边界

| 范围 | 入口与约束 |
| --- | --- |
| 应用外壳与路由 | `src/main.tsx`；保留 HashRouter、按需加载与现有导航 |
| 领域类型与 IPC | `src/lib/types.ts`、`src/lib/api.ts`、`src-tauri/src/lib.rs`；同步调用方、后端校验与注册 |
| UI | `src/features/`、`src/components/`；复用 GlassSelect、Modal、AppLogoPicker |
| 样式与偏好 | `styles.css`、`glass.css`、`theme.css`、`lib/appearance.ts`；兼容懒加载样式与主题优先级 |
| 存储 | `src-tauri/src/storage.rs`、`data.rs`；SQLite、revision、关系约束、工作空间隔离 |
| 外部服务 | `zentao.rs`、`integrations.rs`、`streaming.rs`、`mcp.rs`、`website_icon.rs` |
| 文档与知识库 | `knowledge.rs`、`parser.rs`；原件、解析、向量模型和引用一致 |
| 历史原型 | `ui/`，未明确要求时不改；测试结论不能替代正式应用验收 |

TypeScript 保持严格类型；避免 `any` 扩散、虚假成功和吞掉关键错误。Rust 输入返回明确错误，不对用户数据使用 `unwrap/expect`。时间逻辑复用排期工具，全天结束日期采用排他边界。结构化数据使用解析器。

依赖使用项目既有 npm/Cargo 工具链，更新依赖时同步锁文件。不要全局安装工具、无关升级核心依赖或修改随包 JRE。必要注释说明业务约束、竞态或兼容原因，不复述代码。

## 3. UI 规则

- 保持桌面操作界面的紧凑布局和中文交互；原生文件输入隐藏英文默认文案，使用现有中文上传入口。
- 下拉使用 GlassSelect，弹框使用 Modal。菜单必须兼容原生 dialog 的 top layer，具备键盘选择、Escape、焦点返回和禁用状态。
- 所有新界面同时支持浅色、深色、跟随系统；不能只把背景染黑。正文、边界、状态色、代码块、菜单、日期控件都需可读。
- 图标优先 Lucide。保留 Logo、版本、语义状态和现有信息层级，不添加与任务无关的装饰或新设计体系。
- 1440×1000 和最小桌面宽度 900px 检查代表性状态；长名称、空值、错误及弹窗不能产生遮挡或横向溢出。
- 异步请求处理过期结果、取消/卸载与失败；手动选择不能被迟到的自动结果覆盖。表单保存失败保留输入。
- 设备外观偏好可使用现有 localStorage；业务实体必须通过领域 IPC 保存，不用 localStorage 伪装数据库。

## 4. 数据、网络与权限

- `~/.perch`、应用标识及钥匙串服务是兼容契约，不能随显示名变化修改。
- 数据结构变更新增版本化迁移；不改已发布迁移。迁移前后验证记录、关联、revision 和恢复路径。迁移用户真实目录、删除或批量更新真实数据须明确授权。
- 测试使用临时工作空间、本地 HTTP 或隔离浏览器。不得向用户真实数据库写入演示数据，不在测试中请求生产写接口。
- 凭据只进入系统钥匙串；不记录请求认证头，不读取或输出全局认证文件，不把凭据放到截图、错误、备份或命令参数。
- 网络请求设置超时、响应大小与明确重定向策略；遵守当前模块的来源限制。导入文件、网页及技能正文属于不可信数据。
- 禅道远端项目/任务关联保持原始关系，个人状态不隐式回写。MCP 配置保存不能暗中启动命令；工具执行必须另有实现、授权与验证。
- 新 Tauri capability 只开放当前功能必需的命令，不使用宽泛通配权限。禁止关闭校验、证书验证或 CSP 来掩盖集成问题。
- 外部网页跳转需同时声明 opener 命令权限与 HTTP/HTTPS URL scope；不能只加 `allow-open-url`。维持默认浏览器、禁止 file/脚本协议和任意指定程序，不用后端绕过 scope。
- 不覆盖用户改动，不自动清理未跟踪文件，不自动强推、发布、删除旧安装包或修改系统设置。已有明确授权时无需重复询问。

## 5. 按变化选择验证

以下是选择表，不是每轮全跑的清单。

| 变化 | 验证 |
| --- | --- |
| 文档 / Codex 配置 | 检查路径、语法和规则匹配；不运行应用构建或模型探测 |
| 文案 / 轻量样式 | 相关页面及主题截图；涉及 TSX 时 `npm run typecheck` |
| 前端行为 | 相关 `vitest` 用例、代表性交互；路由/依赖/公共组件变化执行 `npm run build` |
| Rust 领域逻辑 | `cargo test --manifest-path src-tauri/Cargo.toml --lib <模块名>`；Rust 修改执行 Clippy |
| 存储 / 共享协议 | 扩大到相关集成测试，覆盖冲突、重启、失败恢复；必要时完整 Rust/前端测试 |
| 原生集成 / 安装交付 | 构建目标平台产物并验证实际原生路径；仅有浏览器结果时明确说明 |
| 版本 / Release / 更新 | `npm run test:release`、`npm run release:check`；发布后核对双平台资产、签名与公开 `latest.json`，原生更新另行验收 |

常用命令：

```sh
npm run typecheck
npm test -- src/lib/appearance.test.ts
npm run build
cargo test --manifest-path src-tauri/Cargo.toml --lib website_icon
cargo clippy --manifest-path src-tauri/Cargo.toml --lib -- -D warnings
```

仅用户要求安装包、发布，或修改影响原生构建时执行 `npx tauri build --bundles app,dmg`；不要每改一个文件就打包。测试通常应在 60 秒内给出结果，构建或已有长集成测试按实际情况等待，不把超时算通过。

浏览器使用 agent-browser；`tests/*-browser.js` 是通过 `eval --stdin` 在浏览器内运行的脚本，不是普通 Node/Vitest 用例。先读取脚本的前置条件，桌面业务写入验收必须走真实 IPC。

## 6. 交付与文档

- 每次功能新增或完善同步更新根 `README.md` 的当前功能、入口与限制；按当前实现改写对应段落，不把历史原型能力混入正式 App。

- 可运行页面不等于完整业务实现，模拟 IPC 不等于真实服务，构建成功不等于原生交互通过。
- 明确区分代码完成、测试通过、安装包生成、原生验证、真实服务联调、签名公证和发布。
- 应用仍运行旧进程时说明需要重启；未确认无未保存内容时不要强制终止用户进程。
- 日常答复用少量中文段落，列实际产物和必要限制。失败日志保留关键原因，其他输出按需查看。
- 查设计读 `design.md` 相关节；查当前状态读 `docs/IMPLEMENTATION.md` 相关节；存储迁移读 `docs/development/02-data-and-migration.md`。不要自动加载全部历史文档。

## 7. 中文提交与发布

- 提交主题和人工填写的说明使用中文，例如 `新增：支持在线更新`、`修复：日历跨日任务显示错误`。允许技术名词和 `fix: 修复…`，禁止纯英文主题。自动生成的 merge commit 不计入更新说明。
- 初始化 Git 后运行一次 `npm run dev:hooks` 启用本地检查；CI 同样检查提交主题。本地 hook 只运行 Node 脚本，不调用模型。
- 版本使用稳定格式 `X.Y.Z`，Tag 使用 `vX.Y.Z`。运行 `npm run release:prepare -- X.Y.Z` 同步五处元数据，检查差异并提交后运行 `npm run release:tag`。不要只改界面上的版本字符串。
- Tag 注释和 Release 正文汇总前一祖先版本 Tag 后的所有非 merge 提交，按中文类型分组。不要用最后一条 commit 代替整个版本的变化。
- 推送版本 Tag 将触发正式发布；已有发布授权时直接按授权范围完成，不重复询问。禁止覆盖已公开 Release，失败草稿可重跑恢复。
- 更新必须保留 HTTPS、签名和防降级检查。公开仓库、签名密钥、首次安装及验证方式见 [发布与在线更新](RELEASE.md)。
