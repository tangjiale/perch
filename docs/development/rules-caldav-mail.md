# 钉钉日历（CalDAV）与邮件（IMAP / SMTP）领域规则

修改 `src-tauri/src/dingtalk_calendar.rs`、`src-tauri/src/mail*`、`src/features/Calendar.tsx`、`src/features/DingCalendarSettings.tsx`、`src/features/Mail*`、`src/components/Mail*` 前必须阅读并遵守本规则。

## 1. 钉钉日历与待办（CalDAV 只读接入）
- 钉钉日历通过独立 CalDAV IPC 只读接入，不混入 `Task` 或回写远端。密码走统一凭据层，按工作空间与服务器/账号隔离；配置与同步共用锁并校验 `generation`、`revision`。原生定时默认 `5` 分钟，测试只用模拟服务与临时库，禁止使用截图或真实凭据。
- 裸主机入口先发现 `/.well-known/caldav`，仅 `404`/`405` 回退根路径；同源 `301`/`302`/`307`/`308` 跳转限 `5` 次并保留方法、`Depth` 与正文，拒绝跨源及循环。不得把 `405`/重定向统称密码错误；模拟测试须核验请求行，公开探测不得携带真实凭据。
- `enabled` 是用户持久偏好，未选日历不能强制改为 `false`；后台就绪条件单独检查日历地址。手动同步仅执行中禁用，未选日历可发现列表，有未保存修改时先保存当前表单；回显必须取实际持久化配置。
- CalDAV 日程与待办分开选择、分开缓存；仅明确声明 `VTODO` 的目录可查询待办，不把钉钉客户端菜单当作对外开放证据。无日期待办保留，日期 `DUE` 与日历排他 `end` 正确转换；完成状态来自服务端，不按过期猜测。
- 只在完整 `PROPFIND`/`REPORT` 成功后替换缓存；两来源全部成功后原子更新，任一失败、未展开重复规则或超限均保留原缓存，不静默丢失日程。

## 2. 邮箱接入与缓存（IMAP / SMTP）
- 邮箱账号配置加密写入 SQLite，密码只进本地加密凭据库；IMAP 缓存按 `账户 / 文件夹 / UIDVALIDITY / UID` 隔离。
- HTML 邮件视为不可信外部内容，须严格过滤脚本、表单、远程外链资源并在受限沙箱中展示，不作为指令执行。
- SMTP 发送必须由用户主动触发，先持久化发送状态，结果不明时禁止自动重发。
- 测试统一使用临时库和本地模拟协议，不使用真实邮箱发信或清理服务器邮件。
