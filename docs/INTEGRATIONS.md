# 外部集成、Agent 与知识库开发方案

> 状态：已进入实施的目标规格，实际交付与验证见 [实现记录](IMPLEMENTATION.md)。目标为 Tauri 2 + React + Rust + SQLite，先交付 macOS，保持 Windows 可移植性。本文细化禅道、模型、技能、知识库和后台作业的接口及验收标准；不表示全部接口契约均已实现。

## 1. 实现边界

- React 通过受限 Tauri commands 访问领域服务。禅道请求、模型请求、文件处理、数据库访问和凭据读取均由 Rust 执行。
- SQLite 是业务正文和元信息的权威来源。导入文档原件作为受管文件保存；Markdown 是技能/消息的正文格式及交换格式，不作为另一份自动双向同步数据库。
- 单机可离线维护项目、任务、应用、技能和已有会话。网络不可用时保留缓存；需要远端模型、远端禅道的动作明确失败或排队，不伪装完成。
- 桌面进程退出后后台作业暂停。首版不承诺关闭应用后继续同步、解析或通知，不安装系统常驻服务。
- 禅道开源版 22.0 的实际 API 能力必须通过目标实例确认。技能中的 REST v2 文档是调查线索，不能直接当成 22.0 的接口清单。

## 2. 通用接口与错误约定

### 2.1 Command 与事件

命令负责校验和持久化；耗时工作返回 `jobId` 或 `generationId`，不让 WebView 等待整段长任务。本文把一次聊天生成称为 run，物理实体统一为 `chat_generations`。以下接口与 [开发契约](DEVELOPMENT.md) 一致，正式类型由 Rust DTO 生成 TypeScript 类型并纳入版本控制。

```ts
type CommandError = {
  code: string;
  message: string;
  retryable: boolean;
  requestId: string;
  fieldErrors?: Record<string, string>;
};

type ProgressEvent = {
  entityId: string;
  jobId: string;
  seq: number;
  state: string;
  completed?: number;
  total?: number;
};

// 代表性命令，参数均由 Rust 重新验证。
zentao_test_connection({ connectionId }): Promise<ConnectionProbe>;
zentao_sync_start({ connectionId, scope }): Promise<{ jobId: string }>;
zentao_operation_prepare({ externalObjectId, action, draft }): Promise<OperationPreview>;
zentao_operation_confirm({ confirmationId }): Promise<{ jobId: string }>;
provider_test({ providerId, modelId, purpose }): Promise<ProviderProbe>;
chat_send({ conversationId, mutationId, text, knowledgeBaseId, channel }): Promise<{ generationId: string }>;
chat_cancel({ generationId }): Promise<void>;
knowledge_import({ knowledgeBaseId, pickedFileHandles }): Promise<{ jobIds: string[] }>;
knowledge_reindex({ knowledgeBaseId, modelRevisionId }): Promise<{ jobId: string }>;
job_cancel({ jobId }): Promise<void>;
job_retry({ jobId }): Promise<{ jobId: string }>;
```

文件参数使用 Rust 文件选择器生成的短期句柄。前端不传任意系统路径，也不拥有通用 Shell、HTTP 或文件系统调用权限。命令根据领域对象 ID 定位受管文件。

低频前端事件仅用于刷新；事件丢失、WebView 重载时，通过 `job_get`、`chat_generation_get`、`messages_query` 重新读取持久化状态。聊天 token 走 Tauri Channel，事件携带 `generationId + seq + type`；前端忽略旧 generation 和重复序号，避免切换会话后把回复写到其他会话。

### 2.2 统一错误语义

| 错误代码 | 含义与界面处理 | 自动重试 |
| --- | --- | --- |
| `VALIDATION_FAILED` | 表单字段无效，保留用户输入 | 否 |
| `CREDENTIAL_REQUIRED` | 未配置、已清除或系统凭据库不可用 | 否 |
| `AUTH_EXPIRED` / `FORBIDDEN` | 重新认证或检查权限，缓存继续可读 | 否 |
| `NETWORK_UNAVAILABLE` / `RATE_LIMITED` | 显示失败阶段及下次尝试时间 | 只对可安全重试的作业 |
| `CAPABILITY_UNSUPPORTED` | 当前协议、模型或禅道实例不支持 | 否 |
| `CONFLICT` | 对象在准备操作后已变化，刷新后重新准备 | 否 |
| `REMOTE_OUTCOME_UNKNOWN` | 请求可能已生效，先远端回查 | 禁止盲目重放写请求 |
| `FILE_UNSUPPORTED` / `FILE_CORRUPT` / `FILE_ENCRYPTED` | 指出文件与原因，允许替换原件 | 否 |
| `PARSER_TIMEOUT` / `RESOURCE_LIMIT` | 中断解析子进程，保留失败记录 | 人工重试 |
| `EMBEDDING_MISMATCH` | 维度或模型指纹与索引不一致 | 否，需重索引 |
| `INDEX_NOT_READY` | 尚未有可用索引，禁止伪造检索结果 | 否 |
| `CANCELED` / `INTERRUPTED` | 用户停止或应用退出，保留已有进度 | 按作业类型 |
| `DISK_FULL` | 停止写入并提示释放空间，保留原有可用数据 | 否 |

日志保留脱敏错误码、耗时、HTTP 状态、对象 ID 和 trace ID。禁止记录令牌、密码、Authorization、完整模型请求、文档全文和用户本机绝对路径。调试正文日志必须为独立显式开关，默认关闭。

## 3. 禅道开源版 22.0

2026-09-08 已完成官方 22.0 源码的认证核验，新增账号登录自动获取 Token；浏览器 OAuth 回调未作为内置能力发现。证据、固定 v1 Token 入口、REST v2 区分及真实实例验收边界见 [22.0 认证核验](compatibility/zentao-22.0.md)。

### 3.1 适配层与兼容性门禁

定义 `ZentaoAdapter`，领域逻辑不依赖某个 API 路径或远端状态枚举。适配层输出统一 DTO：项目、执行、执行内任务、账号权限、能力清单和远端链接。

在真实接入开发前，针对用户实际的 22.0 测试实例形成 `compatibility/zentao-22.0.md`，至少记录：实例版本及社区/商业版本、子路径部署、认证接口和过期规则、读取入口、分页规则、任务所属执行/项目字段、可用操作与必填字段、状态枚举、日期/时区含义、错误响应。清单中不能写真实凭据。

| 能力 | 当前设计要求 | 22.0 证据要求 |
| --- | --- | --- |
| 测试连接与取令牌 | 获取当前用户并验证权限，显示真实结果 | 实际认证流程和令牌有效期 |
| 项目读取 | 显示独立禅道项目来源 | 全量分页、筛选、不可访问项目样本 |
| 执行读取 | 执行保留类型与所属项目 | 列表、详情、跨项目关系变更样本 |
| 执行内任务读取 | 任务与执行、项目关系一致 | 真实所属字段及分页样本 |
| 编辑及状态流转 | 仅显示已核验且当前可用的操作 | 每个动作单独测试权限、状态、必填字段 |
| 创建远端项目/任务 | 后续管理能力可扩展，不作为本地新建默认行为 | 创建接口与幂等/回查条件单独评审 |

不通过探测写接口来判断权限，不用生产对象试运行。没有验证的管理能力显示“在禅道中管理”，由系统浏览器打开已校验的来源 URL。若实例不支持所需 REST 能力，记录缺失并选择经核验的替代官方接口；不通过抓页面或猜接口宣布支持。

令牌帮助弹窗按该连接使用的真实认证方案解释获取步骤。密码只用于明确的登录取令牌动作，除用户显式选择持久化账号密码外不保存；令牌进入系统凭据库。前端只读到“已配置/失效”等状态，不能回读凭据值。

### 3.2 外部身份和数据所有权

外部唯一键为 `(connection_id, remote_type, remote_id)`，`remote_type` 取 `project | execution | task`。远端 ID 按字符串保存，不假设跨实例唯一。连接在原地址修改到另一台实例时，需要“替换连接”流程或新建连接，不直接复用旧外部身份。

| 数据 | 权威来源 | 同步行为 |
| --- | --- | --- |
| 远端标题、状态、优先级、所属项目/执行、远端周期 | 禅道 | 成功同步后更新远端字段 |
| 本地状态、个人优先级、个人备注、个人计划日期、开始/结束时间 | 工作台 | 同步永不覆盖 |
| 禅道条目的 `project_id` | 禅道关系经外部 ID 解析 | 本地不可移动，远端变更后事务更新 |
| 本地任务关联的项目 | 工作台 | 可选本地或禅道项目，不隐式上传 |
| 初次导入的本地状态 | 已核验远端状态映射 | 仅创建时初始化一次 |

远端 `execution` 不伪装为 `task`。当前 E-* 设计条目按执行导入，后续真实任务使用 `remote_type=task`。远端状态图标按 `remote_status` 显示；本地看板按 `local_status` 显示。未知远端状态使用原值及中性色，不猜测为“已完成”。

### 3.3 同步流程

```text
排队 -> 验证连接/读取范围 -> 拉取完整分页到暂存区
     -> 校验项目/执行/任务关系 -> 事务合并 -> 记录同步结果
```

1. 同一连接同一同步范围只允许一个活动读取作业，后续点击复用 `jobId`。
2. 初版手动和应用启动时同步。优先完成全量分页再优化增量；若无可靠的远端更新时间游标，不声称支持增量同步。
3. 按项目、执行、执行内任务顺序解析关系，网络请求期间不持有数据库写事务。临时表按 `sync_run_id` 隔离；合并前验证必须的父引用存在。
4. 合并在短事务内 upsert 外部字段和关系，不覆盖个人字段。关联父项目无法读取时保留上次关系并标记 `relation_unresolved`；首次导入无法解析则留在同步异常清单，不按名称绑定。
5. 页请求失败、权限不足或范围变更时，不以“本轮没返回”推断远端删除。仅完整且明确覆盖的扫描可将原对象标记 `unavailable`，也不得物理删除本地记录。
6. 新建本地任务时即便选中禅道项目，也保持 `source=local`。关闭连接后缓存可查，远端链接和同步显示不可用。
7. 只在事务成功后更新 `last_success_at` 和下一轮游标。同步日志区分拉取数、更新数、跳过数、异常数和范围；失败不得推进游标。

### 3.4 显式远端管理

默认 `management_enabled=false`。用户开启后，动作集合仍由“适配器已验证能力 ∩ 账号权限 ∩ 对象当前状态”决定。拖拽看板、更改个人状态和编辑个人排期永远不调用远端写接口。

两阶段动作：

1. `prepare` 重新读取远端详情，计算字段差异，验证必填项，生成短期 `operationId`。预览显示连接、对象类型/编号、标题、动作、前后值和潜在业务影响。
2. 用户点击确认后，`zentao_operation_confirm` 根据 Rust 记录的短期 `confirmationId` 执行已准备操作；绑定连接、对象、差异哈希、有效期和窗口，消费一次后失效。不能靠前端传 `confirmed=true` 绕过准备与校验。该机制防误调用，不能将已被完全攻陷的授权窗口视为可信审批者。
3. 写前重新校验远端修订/关键字段哈希。远端支持条件更新时使用其并发控制；不支持时只能缩短检查窗口，仍可能有并发竞争，需明确记录该限制。
4. 请求成功后重新读取实际远端值并刷新缓存。超时或断线形成 `REMOTE_OUTCOME_UNKNOWN`，进入回查状态；远端没有幂等键且无法可靠判断结果时，要求用户在禅道检查后再决定，不自动重发。
5. 操作日志保存对象、动作、字段差异、发起入口、确认时间、结果和远端回读状态。后台读取作业不得消费或生成写操作。

远端删除、批量写、自动代办审批不属于首版默认管理动作。是否增加必须有独立产品设计和实际接口验收，不能由提示词或技能自行扩大范围。

## 4. 大模型供应商与凭据

### 4.1 模型目录和协议

供应商与模型使用稳定内部 ID，远端模型名保存在 `remote_model_id`。能力分为 `chat`、`vision`、`embedding`；不能由名字含“Embedding”就自动判定。模型目录允许手工添加，自动发现结果需用户选择后落库。

完整版本必须交付现有 UI 的三种协议：`openai-completions`、`openai-responses`、`anthropic-messages`，以及独立的 OpenAI 兼容 Embeddings 能力。P4/P5 先完成 Chat Completions，再完成 Responses 和 Anthropic 的原生请求、认证、SSE 事件、usage、停止与错误转换，各自使用合同测试和真实服务 smoke。DeepSeek 和用户自定义兼容服务通过兼容适配器接入。Ollama 原生协议属于后续扩展；支持其兼容 endpoint 不等于支持其原生协议。

对话协议不自动提供 embedding。Anthropic Messages 或仅 Responses 的供应商未实现向量入口时不允许绑定知识库；可另外配置提供兼容 Embeddings 的供应商。同一供应商要声明独立的 chat/embedding endpoint 能力，不能把 embedding 请求发到消息地址。协议测试矩阵分别记录 endpoint、认证 header、消息角色映射、图片支持、上下文上限与流结束规则，具体协议版本在 P0 对照官方文档核验。

```rust
// 概念接口，使用固定版本依赖实现，不要求直接照抄签名。
trait ProviderAdapter {
    async fn probe(&self, config: ProbeConfig) -> Result<ProviderProbe>;
    async fn list_models(&self) -> Result<Vec<DiscoveredModel>>;
    async fn chat(&self, input: ChatRequest, sink: EventSink, cancel: CancelToken)
        -> Result<ChatOutcome>;
    async fn embed(&self, input: EmbedRequest, cancel: CancelToken)
        -> Result<Vec<Embedding>>;
}
```

适配器负责路径组合、协议字段转换、流式解析、usage 归一化、错误映射和参数兼容。Base URL 保存为 API 根路径，明确是否包含 `/v1`；使用 URL 库拼接，不简单追加字符串造成 `/v1/v1`。不支持的 `temperature`、工具调用或图片输入在发送前报错，不静默丢弃用户配置。

测试连接分为“地址/认证可达”“指定对话模型最小请求”“指定 embedding 模型最小请求”。列模型成功不等于模型推理成功。embedding 检查返回条数、浮点合法性、维度及非零向量，并保存测试时间。

### 4.2 网络与密钥

- API 密钥和禅道令牌保存 macOS Keychain，Windows 后续使用平台凭据库；SQLite 只保存 `credential_ref`。备份、迁移包和 UI 不包含明文密钥，迁移后重新配置。
- Rust 客户端验证 TLS，禁止全局关闭证书校验。公司私有 CA 使用该连接的受控证书配置。远端 HTTP 显示风险并要求显式选择；本机 loopback HTTP 允许用于本地模型。
- 跟随重定向前重新检查源站；禁止把认证头转发至其他源站。供应商地址变更需要重新测试和确认，以免旧密钥发往新地址。
- 错误响应正文截断并脱敏。凭据值不写入聊天快照；快照记录配置版本、供应商 ID、远端模型 ID、参数和能力。端点由不可变 `model_revisions.base_url` 保留，仅配置界面和受控数据迁移可读取，不记录于日志或消息正文；旧端点不得无提示地复用新主机的密钥。
- 向远端 embedding 服务发送文档正文前，知识库设置必须标明供应商和发送范围。文档在本地存储不代表其向量化必然离线；选择本地服务才可使该流程不出本机。

### 4.3 流式对话与取消

`chat_send` 用 `conversation_id + mutation_id` 去重，在事务内创建用户消息、待生成助手消息及 run，再启动请求。同一会话一次一个活动 run；首版全局对话并发上限为 2，可在压测后调整。

```text
queued -> retrieving -> requesting -> streaming -> completed
    任一活动阶段 -> canceled / failed / interrupted
```

以上状态属于 `chat_generations.status`；对应助手 `messages.status` 使用 pending/streaming/completed/stopped/failed/interrupted，其中 canceled 映射为 stopped。后台导入的 queued/running/succeeded 状态只用于 `background_jobs`，不混写消息状态。

- SSE 使用增量解析器，处理 UTF-8 跨包、分片 JSON、事件注释、结束标记和断流。不能假设每个网络 chunk 是一条完整事件。
- 收到片段后按约 250 ms 或 4 KB 批量落盘，终态必须强制 flush；异常退出最多丢失最后一个未落盘批次，界面标记中断。
- 停止按钮触发 Rust cancellation token，取消检索/HTTP 和待执行工具；保留已产生文字，并记录 `finish_reason=canceled`。本地取消不保证远端供应商停止计费。
- 只有明确未提交请求或服务明确拒绝请求（例如 429）时允许有限重试。服务可能已经接收而本地未见输出的断线仍可能计费，不自动重发；收到文本或工具动作后也不自动重发。重新生成创建新的 run，并显式保留与上一版的关系。
- 用户切换页面不等于取消；删除活动会话必须先取消、等待终态，再按删除策略处理。应用恢复后将残留活动 run 标为 `interrupted`，不自动续发收费请求。
- usage 仅在供应商真实返回时显示；本地估算需注明估算，不能当作计费事实。

## 5. Agent 与技能

### 5.1 配置快照

Agent 支持名称、描述、图标、提示词、供应商/模型、参数、启停、复制、技能关联。embedding 模型不出现在对话模型列表。被 Agent 或知识库引用的供应商/模型禁止直接删除；列出引用对象，引导迁移或停用。

新建会话固定不可变配置快照：物理上以 `conversations.agent_revision_id` 关联 `agent_revisions`、`model_revisions`、`agent_revision_skills` 和 `skill_revisions`，保留提示词、参数、模型绑定、技能顺序/正文哈希及正文。无需再维护可独立改写的 `agent_snapshot` 副本。后续编辑 Agent 或技能不改写历史会话；用户需创建新会话应用更新。供应商停用、模型停用和凭据失效属于实时可用性检查，即使有旧快照也不能继续发送。

已建立会话的模型绑定不静默变更。被引用模型的远端标识/协议修改需新建模型修订并显式迁移；旧会话可以阅读，继续对话前明确选择创建新会话。凭据轮换不改变语义快照。

### 5.2 技能创建与导入

首版技能为“带元信息的提示词正文”，可编辑、启停、导入、复制、删除。输入格式为 Markdown / `SKILL.md` 和受版本约束 JSON：

```yaml
---
name: 会议纪要
description: 整理讨论结论与行动项
---
依据提供的会议内容整理决策、行动项、负责人和期限。
```

YAML 使用成熟解析器并禁用自定义标签/对象构造，限制别名展开、正文大小及嵌套深度。JSON 使用结构化解析和 schema 校验。文件上限沿用预览的 256 KB，文本统一解码为 UTF-8；同名导入提示“创建副本”或“更新现有技能”，更新生成修订。

导入先展示名称、描述、正文预览及差异，再确认保存。技能中的链接、命令、文件路径及 `scripts/` 说明都是内容，不执行 Shell、不下载依赖、不读取正文引用的本机文件。首版不接收可执行技能包；未来包导入必须另设签名、依赖与执行隔离方案。

技能停用影响新会话配置，历史快照继续可读。已有 Agent 或会话引用时禁止硬删除，采用归档/停用，管理界面列出影响；无引用技能才允许确认后删除。因安全原因撤销某技能的后续调用，应单独保存撤销标记并在每次 run 前检查，不能仅依赖旧快照。

### 5.3 工具权限

技能正文不授予系统权限。工具通过 Rust 的注册表和 JSON schema 定义，Agent 配置只引用可选工具，运行时再与全局权限取交集。

| 工具类别 | 首版策略 |
| --- | --- |
| 读取任务、项目、日历、应用 | 默认关闭，用户给 Agent 开启后按结构化查询执行，限制结果数量 |
| 知识库检索 | 仅当前消息已选择的库及已就绪 generation |
| 新建/修改本地任务 | 首版可作为受控扩展；必须呈现结构化草稿，用户确认后写入 |
| 禅道远端写 | 默认关闭，只有已验证动作可进入第 3.4 节同一准备/确认流程 |
| 任意 Shell、SQL、任意文件读写、任意 URL 请求 | 不注册此类通用工具 |

远端页面、文档片段和工具结果均为不可信数据，不升级为系统指令。提示词隔离只是辅助，真正边界由工具注册表和后端鉴权执行。每个 run 限制工具轮数、单次执行时长和输出大小；建议初值 8 轮、单工具 30 秒、输出 32 KB，超限停止并说明原因。

工具调用日志关联 `run_id`、`tool_call_id`、工具名、参数摘要、批准事件和实际结果。没有成功工具结果的回复不得被 UI 展示为“任务已更新”；本地/远端写操作以应用事实卡片展示状态，模型文本不作为提交依据。

## 6. 知识库与文件解析

### 6.1 数据流和来源

```text
选择原件 -> 校验/复制受管目录 -> 提取正文 -> 规范化/分块
        -> 调用 embedding -> 写入候选 generation -> 激活索引
聊天问题 -> 同模型 embedding + 分词检索 -> 合并排名 -> 片段 -> 回复引用
```

每个知识库可包含多份文档，绑定一个明确的 embedding 配置。原件内容哈希 `SHA-256` 用于一致性和同内容提示；文件名不作为身份。同名文件不能静默覆盖，用户可新增文档或替换并创建新文档修订。

知识库元信息、抽取正文、分块、向量、索引版本和引用记录保存在 SQLite；原件保存为应用数据目录下的受管文件。用户原始文件移动或删除后不影响已导入内容。文件系统布局、归档和迁移以数据文档为准。

### 6.2 格式和解析器选型

| 格式 | 基线实现 | 引用定位与限制 |
| --- | --- | --- |
| TXT / MD | Rust 文本解码，成熟 Markdown parser 读取段落/标题 | 行号、标题路径；不执行 HTML 或代码块 |
| DOCX / DOC | 附带 Apache Tika 解析子进程 | 段落/标题；无可靠分页时不生成页码 |
| PPTX / PPT | Tika 提取幻灯片正文与元信息 | 只有解析器实际提供页序时使用幻灯片号 |
| XLSX / XLS | Tika 表格抽取适配 | 保留工作表及行列关系；若只能返回扁平文本明确降级，不伪造单元格引用 |
| PDF | Tika/PDFBox 提取可选中文字 | 实际页码和段落；扫描件需 OCR |

选择 Apache Tika 是为了覆盖 Office 新旧格式与 PDF，避免自行实现二进制解析器。正式实现需固定 Tika、Java LTS 与依赖版本，随安装包附带裁剪的 Java runtime，不要求用户安装 Java、Microsoft Office 或 LibreOffice。离线安装后立即具备解析能力。

Tauri 调用受控的原生 launcher，launcher 再以绝对路径启动随包 Java。React 无启动子进程权限。Tika 用固定的 request/result 协议通过管道交换，不启动对局域网开放的 HTTP 服务；输入仅允许受管原件，输出写入随机隔离的临时目录。

受控子进程不是强安全沙箱。首版使用进程隔离、低权限运行、关闭宏执行/外部资源下载/嵌入对象递归提取、文件大小/解压总量/耗时限制和定期依赖更新降低风险。所有限制必须对应解析器配置或 wrapper 实现并测试，不能仅在文档中写“禁止联网”就认为有操作系统网络隔离。更强隔离需另行评估 macOS Sandbox/Windows AppContainer；不把它作为已具备能力。

建议初始限制：原件 30 MB，解析并发 1，单件解析 120 秒，Java heap 512 MB，解压总量 200 MB，归档条目 10,000，抽取文本 20 MB。超限保留原件，返回可理解错误。操作系统 RSS 可能高于 heap，需监控和强制终止阈值；最终阈值在目标 Mac 的真实样本测试后固定。

旧 DOC/PPT/XLS 和复杂表格是发布门禁：必须使用真实中文样本对抽取结果人工核对。若某格式在当前构建中失败，上传后显示不支持/解析失败并说明转换建议，不能把“扩展名接收成功”算成支持。嵌入文件、公式结果、隐藏工作表、讲者备注的抽取范围必须在样本测试中明确。

OCR 是独立能力，不在普通 PDF 文本提取中自动宣称完成。扫描文档返回 `needs_ocr`；首版允许保存原件并提示没有可检索正文。若把扫描件纳入正式首版验收，需明确追加 OCR 引擎、中文模型包、页渲染、签名体积和质量门禁，再改为 OCR 作业流程。

### 6.3 文档状态

```text
pending -> validating -> extracting -> chunking -> embedding -> ready
                    -> failed / needs_ocr / canceled
ready -> 新修订处理中 -> 新修订 ready 后切换
```

文档展示文件名、格式、大小、导入时间、状态、进度、最近错误、当前 revision、索引模型和分块数。重试从失败阶段的有效检查点继续；取消不能把半成品标记 ready。文档删除需要确认；活动作业取消后，事务中撤销新检索资格，再从数据库合法引用集合计算原件清理资格，历史引用按保留策略处理。

### 6.4 分块和 embedding

抽取后保留结构化定位信息，移除重复页眉页脚等处理必须有可回溯规则版本。按标题、段落、表格行组先分段，再按模型 tokenizer 约 600 tokens 切块、80 tokens 重叠；模型硬上限更低时相应缩小。无法取得精确 tokenizer 时采用保守字节/字符上限并对超长输入递归拆分，不声称 token 数精确。

每块保存 `document_id`、`document_revision_id`、`chunk_id`、顺序、文本、正文哈希、定位信息、parser/chunker 版本。表格标题重复进入相邻块，正文引用定位仍指向原始行；不能用任意换行拆分把表头和数据永久分离。

embedding 请求按 token/条数/供应商限制分批，检查返回索引与条数一一对应、维度一致、浮点有限且范数非零。向量以 little-endian float32 BLOB 存储，记录维度和归一化规则；读取验证字节长度等于 `dimension * 4`。

索引指纹至少包括供应商 ID、模型内部修订、远端模型 ID/声明版本、端点配置修订、维度、归一化、parser/chunker 版本。供应商沿用同名模型却更换权重无法仅靠 API 自动识别，需要用户显式提升模型修订或部署版本；升级后触发重索引，不混用向量。

### 6.5 检索基线

首版向量检索使用 SQLite BLOB + Rust 精确余弦，便于备份和跨平台迁移。对当前选中的知识库、活动 generation、未删除的文档修订做过滤后扫描，使用有界 Top-K heap，时间约 `O(N*d + N*log K)`，不得在 WebView 主线程计算。

统一上线基准为单库 10,000 块、1,024 维，在记录配置的目标 Mac 上测试冷/热检索和峰值内存，目标本地检索 P95 ≤ 1 秒，不计模型网络时间。20,000 × 1,536 和 20,000 × 4,096 作为扩容压力测试，不作为已验证容量承诺。未通过则优化或引入经验证的加速实现。

`sqlite-vec` 是可选加速后端，只有精度等价、macOS 架构兼容、签名/公证和备份恢复测试通过后启用。首版不允许用户任意加载 SQLite 扩展；优先静态编译或随包签名组件，扩展索引视为可重建派生数据。

全文检索使用 SQLite FTS5，但默认 `unicode61` 不能作为中文分词方案。使用 Rust 成熟中文分词器（如 `jieba-rs`）对文本和问题执行同一版本的词元化，保存词元串进入 FTS5；英文保留大小写归一化规则，原文和定位保持不变。分词词典/版本变化需重建全文索引。

混合检索初始取向量 Top 20 和全文 Top 20，使用 RRF 合并，按来源去重后最多选 8 个片段，并限制总上下文预算。参数为可配置工程常量，经中文问题集调优。首版不强制另配 reranker，不把两个不可比较的原始分数直接相加。

### 6.6 聊天引用与索引切换

聊天每条消息可选择一个知识库或不使用知识库，与现有设计一致。发送时固定 `knowledge_base_id`、名称、`generation_id`、embedding 指纹和检索参数。run 活动期间不能变更这条消息的知识库，下一条消息可切换。

检索只使用该库 `active_generation_id` 指向且状态为 `active` 的 generation，不能查询尚未发布的 `ready` 候选代。没有索引时阻止依赖知识库的发送，用户可明确改为“不使用知识库”；检索已成功但没有足够相关内容时，回复说明未找到依据，不制造引用。

每个引用记录真实的 `document_id`、`document_revision_id`、`chunk_id`、`generation_id`、文件显示名、定位信息、片段快照和内容哈希。传给模型的是受限引用 ID；生成后只解析此次检索集合中的 ID，未知引用标记为无效。UI 点引用展示实际片段并可打开受管原件；解析器没给页码时用标题/段落定位。

模型引用了真实片段不等于每句话都被片段支持。验收必须人工比对事实与出处；界面允许查看原文，不能仅以模型格式正确判定答案准确。

更换知识库 embedding 模型需创建新 generation，在旧 generation 继续可查询的条件下完整重建。只有新 generation 所有目标文档达到明确终态、并通过一致性检查后，事务切换 `active_generation_id`。部分失败必须让用户看到范围；默认不切换到缺文档的索引。旧模型不可用时旧索引无法生成查询向量，应显示受影响情况，不能声称重建期间必然可查。

历史消息引用保留自己的片段快照和旧 generation 标识，清理旧向量不破坏历史引用文字。删除原件后历史引用可以显示“原件已删除”，不得链接到同名新文件。已被会话引用的知识库按现有设计阻止直接删除，先归档或处理引用；文档的物理删除与合规清理另设明确操作。

## 7. 后台作业与恢复

### 7.1 作业记录

持久化作业至少包含 `id`、`kind`、`entity_id`、`input_revision`、`dedupe_key`、`state`、`phase`、`attempt`、`next_run_at`、`lease_owner`、`lease_until`、`checkpoint_json`、`cancel_requested`、`error_code` 和时间戳。输入仅保存 ID/配置修订，不保存密钥。

```text
queued -> running -> succeeded
             | -> waiting_retry -> queued
             | -> failed / canceled / interrupted
```

SQLite 事务原子领取任务并续租；单进程仍使用 lease 防止恢复时重复执行。建议 30 秒租期、10 秒续租。UI 展示 `phase` 与真实已处理/总数，未知总数使用不定进度，不制造百分比。

### 7.2 并发与幂等

- 同一禅道连接同步并发 1；同一知识库重索引并发 1；Tika 解析全局并发 1；embedding 全局并发初值 2，并按供应商共享速率限制。
- 文档阶段幂等键使用原件哈希、文档修订、parser/chunker 版本及索引指纹。已写入且校验通过的向量批次可复用，避免崩溃后全量重复收费。
- SQLite 写事务必须短，不在事务内等网络或子进程。数据库迁移、恢复备份期间暂停所有写作业。
- transient 错误初始指数退避 2/5/15 秒、最多 3 次并加入抖动；遵守 `Retry-After`，界面可人工取消。认证错误和格式损坏不重试。
- 聊天生成和远端写操作不是普通可重放导入作业，使用各自的中断/结果未知恢复规则。

### 7.3 文件与崩溃恢复

文件系统与 SQLite 不共享事务，使用明确的中间状态：先将原件复制到临时受管路径、计算哈希并 fsync；原子重命名到受管路径后，再用短事务确认文档修订及解析作业。崩溃恢复扫描只处理应用自己创建的暂存文件，按导入记录校对；无引用受管文件延迟进入回收队列。

启动恢复顺序：执行数据库迁移与完整性检查；标记过期 lease；终止/清理属于本应用的遗留解析任务记录；验证已完成阶段的产物哈希；恢复可幂等读取/解析/embedding 作业；把聊天和结果未知远端写移至人工可见的恢复状态。不要仅凭 PID 杀进程，需校验进程身份和本次启动 token。

文件删除先标记待回收并使其退出新检索，确认没有活动作业、文档版本或导出任务引用后再物理清理。失败可重试，不能出现数据库宣称文件可下载但原件已静默丢失。

## 9. 仍需实例或实现验证的事项

1. 禅道 22.0 实际地址、认证方式、账号权限、项目模式与远端写接口。它们决定集成测试和动作可用性，不阻塞其余本地模块开发。
2. 目标 Mac 的最低系统版本、Intel 支持范围，以及 Tika/Java 随包后的体积、签名、公证和内存表现。
3. 用户真实 Office 文档中的表格、备注、隐藏内容和旧二进制格式质量，不能由通用解析器宣传代替验收。
4. 实际 embedding 服务的维度、上下文上限、批量限制、模型版本稳定性和部署方式。
5. 若要求扫描件全文检索，需把 OCR 从独立追加能力提升为明确交付项；当前基线只保证可提取文字的 PDF。
6. 工具执行首版默认关闭；本地写工具与远端写工具何时启用由对应阶段验收决定，不影响普通 Agent 对话、技能指令和知识库问答交付。
